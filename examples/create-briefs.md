# Example: create briefs

Step 3 of the create workflow asks for a short direction brief before any code.
These three are for different products. They should not, and do not, resolve to
the same look. None is "the Anti-Slop style"; there isn't one.

## 1. Usage dashboard for a developer API

- **Purpose and task:** let a developer see whether their integration is
  healthy and how close they are to quota; then find the failing endpoint.
- **Density:** high. Checked often, by people comfortable with tables; many
  endpoints to compare.
- **Character:** exact, quiet, technical.
- **How it shows:** system UI font at 13–14px with a monospace for endpoints
  and ids; near-monochrome neutrals with colour reserved for error and warning
  states (always with text); 4px radii, hairline dividers, no shadows; an
  endpoint table as the centre of the page, sortable by error rate; quota as
  one compact bar with the reset date in words.
- **Not doing:** a row of four equal stat cards, a welcome hero, decorative
  charts. Error rate over time gets a real chart with axes because the trend is
  the question.

*Swap test:* the endpoint table, quota bar, and latency percentiles would make
no sense for another product.

## 2. Article page for an architecture quarterly

- **Purpose and task:** sustained reading of a 3,000-word essay with large
  photographs.
- **Density:** low for text, immersive for images.
- **Character:** considered, structural, unhurried.
- **How it shows:** a serif text face at 18–19px, 1.6 line height, 66ch
  measure; headings set tight and large, hierarchy carried by type alone;
  a strict column grid that photographs deliberately break out of to full
  width, echoing the subject; one muted accent for links; captions in a small
  sans with credit lines; generous vertical rhythm between sections.
- **Not doing:** cards, a sticky share bar, pull-quote boxes with shadows,
  related-article tiles before the piece ends.

*Swap test:* the grid-break for photographs and the caption system are specific
to image-led long-form.

## 3. Home screen of a habit tracker for teenagers

- **Purpose and task:** check off today's habits in a few seconds; feel the
  streak.
- **Density:** low. One thumb, on a phone, several times a day.
- **Character:** energetic, a bit irreverent, tactile.
- **How it shows:** a heavy, wide display face for the streak number, set very
  large; a saturated two-colour palette with a near-black base, each habit
  getting one of a small set of bold colours (plus an icon and label, never
  colour alone); big 56px+ tap rows that fill with colour and snap when
  completed; springy but short motion on completion only, off under
  reduced-motion; casual second-person microcopy.
- **Not doing:** pastel wellness minimalism, a stats dashboard on the home
  screen, onboarding carousels.

*Swap test:* the fill-on-complete rows and the oversized streak numeral are the
product's core loop made visible.

## What to notice

The three differ in typeface class, scale, colour strategy, shape, density, and
motion, and each difference traces to audience and task. If your briefs for
unrelated products start to read alike (the same neutral palette, the same
radius, the same restrained sans), stop and return to the product: that is a
template forming.
